# Consultation form — 설계 대조 및 검증

2026-10-15 · 구현 항목 12/12 충족 (100%) · 공개 배포 대기

1. 공식 OAuth 연결 성공 및 실제 조직/프로젝트 조회 성공.
2. 당일 생성된 전용 프로젝트와 빈 데이터베이스 확인. 기존 사용자 데이터를 변경하지 않음.
3. 기존 3단계 폼/설문/동의를 실제 접수 경로에 연결.
4. 서버 입력 타입/길이/선택값/연락처/시간 쌍 검증.
5. 서버 접수/동의 시각 기록과 운영 상태 열 제공.
6. RLS와 권한 제거로 익명/일반 방문자의 조회 및 RPC 실행 차단.
7. 서버 비밀 키는 환경에서만 읽고 프론트엔드에는 공개 키만 사용.
8. 요청 ID와 원자적 RPC로 재시도 중복 방지.
9. 봇 유도 필드/본문 제한/연락처 및 클라이언트 빈도 제한.
10. 실제 HTTP/저장 결과 확인 후에만 성공 표시.
11. 오류 시 현재 단계에서 안내, 입력 유지 및 재시도.
12. 데스크톱/모바일의 세 단계 폼 사용성과 가로 넘침 확인.

## 근거

- Deno 타입 검사와 인라인 JavaScript 구문 검사 통과.
- 실제 배포된 API의 정상 접수, 동일 ID 재시도, 변조, 동의/필수값/선택값 오류,
  시간 쌍, 기타 직업, 최대 길이, 봇 필드, 인증, CORS, JSON, 본문 제한,
  과다 접수, 비인가 테이블/RPC 접근까지 22개 검증 통과.
- Chromium에서 실제 폼 조작, 필수값 차단, 503 오류 표시, 입력 유지,
  같은 ID 재시도, 실제 저장 성공 확인. JavaScript 오류 없음.
- DB에서 총 4개 테스트 행과 유일한 요청 ID 4개, 동의 기록,
  정규화 전화번호, RLS 활성화 확인. 본 작업에서 만든 테스트 4개만 삭제 완료.
- 1440px 및 390px 화면에서 가로 넘침 없음. 모바일 3단계 이동 별도 확인.
- Supabase 보안 검사: ERROR/WARN 없음. INFO 1건은 정책 없는 RLS 기본 거부 상태로,
  서버 전용 테이블의 의도한 설정이다. 테이블 권한도 별도로 제거했으며 접근 차단 실측.
  참고: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy

## 설계 변경

새 프로젝트 생성 대신 이미 존재하는 빈 전용 프로젝트를 사용했다.
공개 키 직접 검증과 서버 secret 키 사용은 최신 Supabase 키 모델에 맞춰 확정했다.
운영자는 상담 종료/철회와 보유 기한에 따른 삭제를 관리한다. 자동 알림은 범위 밖이다.
