# Consultation form — design

2026-10-15 · Supabase 연결 및 상담 접수 설계

## 연결

- 웹 Supabase 플러그인은 설치되어 있지만 현재 Codex CLI에 Supabase MCP 서버 설정이 없다.
- 기존 CODEX_HOME의 config.toml에 공식 HTTPS MCP 서버를 CLI로 추가한다.
- 서버: https://mcp.supabase.com/mcp
- 필요한 기능: account, database, development, functions, debugging, docs.
- 로그인은 공식 OAuth 브라우저 흐름으로 진행한다. 로그인과 계정 접근 동의는 사용자가 직접 수행한다.
- 비밀 값은 출력하거나 프로젝트에 저장하지 않는다. 기존 MCP 설정은 유지한다.
- 로그인 완료와 실제 조직 조회 성공을 구분해 기록한다.

## 데이터 흐름

기존 3단계 폼 → HTTPS Edge Function → 비공개 consultation_requests 테이블.
운영자는 Supabase 대시보드에서 상담 요청을 확인한다.

## 데이터와 권한

- 서버 생성 ID/접수 시간, 이름/전화번호/연령대, 상담 가능 시간, 직업/경력/성과/목표/학습 시간/참여 의향/지원 동기, 동의 기록을 보관한다.
- 테이블은 RLS를 활성화하고 익명 및 일반 방문자에게 조회/수정/삭제 권한을 주지 않는다.
- Edge Function만 서버 비밀 키로 검증된 신청을 저장한다. 비밀 키는 브라우저에 포함하지 않는다.
- 입력 길이/선택값/전화번호/필수 동의 및 시간 쌍을 서버에서 검증한다.
- 제출 중 중복 클릭 방지, 요청 식별자를 통한 재시도 중복 방지, 기본 스팸 방어를 적용한다.

## 프론트엔드

- 실제 저장 성공 응답 이후에만 접수 성공 화면을 표시한다.
- 실패하면 현재 단계에서 오류 안내와 재시도를 제공한다.
- 서버 검증과 실제 저장 테스트를 통과하기 전까지 공개 폼은 활성화하지 않는다.

## 검증과 배포

- 인증 후 GFTC 조교단 조직에 당일 생성된 전용 프로젝트 GFTC_월급반_고객폼(rpypknboeestdfvtlcad)이 이미 존재하고 테이블/함수는 비어 있음을 확인했다. 이 전용 프로젝트를 사용하며 별도 프로젝트나 유료 리소스를 추가하지 않는다.
- 정상 신청, 누락/잘못된 값, 동의 없음, 서버 실패, 재시도 중복, 비인가 조회 차단을 확인한다.
- 실제 저장 확인 후 기존 Sites 배포 흐름으로 폼을 공개한다.

## 구현에서 확정한 상세

- 함수는 SUPABASE_PUBLISHABLE_KEYS 환경의 현재 공개 키와 apikey 헤더를 직접 대조한다. 새 공개 키는 JWT가 아니므로 verify_jwt=false이며 자체 키 검증을 반드시 통과해야 한다.
- 서버는 SUPABASE_SECRET_KEYS의 default 키를 메모리에서만 사용한다. 공개 프론트엔드에는 공개 키만 포함한다.
- submit_consultation RPC는 service_role만 실행 가능하며 원자적 중복 방지/빈도 제한을 수행한다.
- 본문 32KiB/지원 동기 5,000자 제한, 봇 유도 필드, 같은 연락처 하루 3건/IP 일별 HMAC 기준 10분 10건 제한을 적용한다.
- 실제 IP는 저장하지 않는다. 동의 시각과 접수 시각은 서버가 기록한다.
- 정확한 공개 사이트 Origin만 브라우저에서 허용한다. 별도 조회용 공개 API는 제공하지 않는다.
