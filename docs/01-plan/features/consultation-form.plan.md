## 목적과 결정

월급반 랜딩페이지의 기존 3단계 상담 신청 폼을 실제 접수로 전환한다. 사용자가 Supabase를 제안했으며, 월급반 전용 프로젝트를 새로 생성하기로 선택했다. 최신 지시에 따라 계정 연결부터 진행한다.

## 현재 상태

- 사이트: https://gftc-wolgeupban.secretpoppy1.chatgpt.site
- 현재 폼은 전송 주소가 비어 있고 제출이 비활성화되어 있다.
- 이름, 전화번호, 연령대, 상담 가능 시간, 설문 응답, 지원 동기, 개인정보 수집 동의를 받는다.
- 웹 Supabase 플러그인 설치는 확인되었다. 현재 Codex CLI에는 별도의 MCP 연결이 없어 공식 원격 MCP 서버를 추가했다.
- Supabase 프로젝트/테이블 생성 및 폼 코드 변경은 아직 하지 않았다.

## 작업 범위

1. 사용자의 OAuth 계정 연결 확인.
2. 접근 가능한 조직과 프로젝트 생성 조건 확인 후 월급반 전용 프로젝트 생성.
3. 상담 데이터 구조, 방문자 제출 전용 경로, 비공개 조회 권한을 설계.
4. 입력 검증, 실제 저장 결과에 따른 성공/실패 처리와 재시도 구현.
5. 테스트 신청의 저장 여부와 비인가 조회 차단을 검증하고 배포.

## 완료 기준

실제 방문자의 신청이 Supabase에 저장되고 운영자가 조회할 수 있다. 다른 방문자는 신청 목록을 읽을 수 없다. 저장 실패를 접수 성공으로 표시하지 않는다. 비밀 키를 브라우저나 소스 저장소에 넣지 않는다.

## 다음 단계

OAuth 인증과 실제 조직 조회를 완료했다. 기존 전용 프로젝트 GFTC_월급반_고객폼에 접수 서버/비공개 테이블을 만들고, 테스트 후 공개 사이트의 폼을 활성화했다. 운영자는 Supabase Table Editor에서 consultation_requests를 확인한다.
